# Memory Card Matching Game

## Overview

This project is a browser-based Memory Card Matching Game built using HTML, CSS, and JavaScript. Players must find all matching pairs of cards before running out of attempts. The game includes multiple board sizes, card shuffling, score tracking, and win/lose conditions.

Prior to developing this project, I was already comfortable working with HTML and CSS but had very limited experience with JavaScript. Building this game provided an opportunity to apply JavaScript in a practical setting and gain experience creating interactive web applications.

---

## Features

* Multiple board sizes:

  * 2x4
  * 4x4
  * 6x4
* Random card shuffling
* Dynamic game board generation
* Card matching logic
* Attempt and click tracking
* Win and lose conditions
* End-game popups
* Responsive and interactive gameplay

---

## Technologies Used

* HTML5
* CSS3
* JavaScript (Vanilla JS)

## Development Process

The main focus of this project was creating an interactive game using JavaScript. While HTML and CSS were used to structure and style the application, much of the functionality is driven through JavaScript.

The project required managing game states, handling user interactions, generating content dynamically, and implementing the logic needed for matching cards and tracking progress throughout the game.

---

## New Key Areas Explored and Learnt

### DOM Manipulation

A significant part of the project involved working with the Document Object Model (DOM). The game board is generated dynamically, with JavaScript creating and updating elements based on the selected board size and the current state of the game.

### Event Handling

User interactions are handled through event listeners, allowing cards to respond to clicks and ensuring gameplay flows correctly. This included managing card selections, preventing invalid moves, and updating the interface in real time.

### Objects and Data Structures

Card information is stored using JavaScript objects, making it easier to manage properties such as card values, images, and match status. Arrays are used throughout the project to organise card data and support features such as shuffling and board generation.

### Game Logic

One of the more challenging aspects of development was implementing the game logic. This includes:

* Detecting matching card pairs
* Tracking player attempts
* Monitoring completed matches
* Determining win and lose conditions
* Resetting and rebuilding the game board when required

Developing these features helped strengthen problem-solving skills and provided experience breaking larger tasks into smaller, manageable functions.

### Debugging and Testing

Throughout development, browser developer tools and console logging were used to monitor application behaviour and troubleshoot issues. Testing different scenarios helped ensure that game mechanics behaved as expected and highlighted areas for improvement.

---

## Challenges

Some of the challenges encountered during development included:

* Managing multiple card states simultaneously
* Preventing users from selecting invalid card combinations
* Correctly tracking game progress across different board sizes
* Ensuring shuffled cards remained paired correctly
* Maintaining clean and reusable code as functionality expanded

Addressing these challenges provided valuable experience working through real-world programming problems and refining solutions through testing and iteration.
